# Anonymised review package

Supplementary material for the submission "Leaderboard Overfitting on Kaggle, Revisited: A Pre-Specified Re-Test and the Limits of Aggregate Scores". Names, account names, machine paths and the public repository and archive links are removed. The full research record, including the dated decision log and the third-party archive links that timestamp the analysis plan, is available to the editor on request and will be public on acceptance.

## Contents

- `analysis_plan/stage2_analysis_plan_v1.0.md` - the plan as archived before any later-competition score was read; `SHA256SUMS.txt` holds its hash and those of the label table and measure code.
- `scripts/` - all analysis code. `scripts/stage2_measures.py` defines every measure.
- `run_all.sh` - runs every stage in order. `CLEAN=1 ./run_all.sh` moves existing outputs aside and recomputes from raw data.
- `data/reference/` - the 120 original competition identifiers transcribed from the 2019 paper's appendix, and the split-label reading decisions.
- `outputs/` - every result table, the reports for each stage, the independent reviewer's counterexamples and checks (`outputs/review/`), and the clean-rebuild comparison (`outputs/rebuild/`).
- `paper/figures/` - the figures as generated by `scripts/stage5_figures.py`.
- `CHRONOLOGY.md` - the order of events, without identities.
- `MANIFEST_SHA256.txt` - hash of every file in this package.

## Running

Python 3.14 with `pip install -r requirements.txt` (or Python 3.12 with `requirements-py312.txt`; both give the same tables), then `CLEAN=1 PY=python bash run_all.sh`. About ten to twenty minutes on a laptop. Then compare with the shipped tables: `python scripts/compare_outputs.py outputs_previous_<time> outputs`. It compares the 35 pipeline tables cell by cell: identifiers, counts (also when written as decimals), labels, true/false flags, missing values and signs must match exactly; p-values must fall on the same side of 0.01, 0.05 and 0.10; other decimals must satisfy |a - b| <= 1e-12 + 1e-9 |b|. It also compares the scientific fields of three JSON result files. Figures are not compared; they are drawn from compared tables. It ends with PASS or a list of failures, and can write a cell-level difference report. `python scripts/compare_outputs.py --selftest` checks the comparison itself against 30 deliberately altered inputs. Without the optional Allstate test file in `data/reference/`, `outputs/stage1/allstate_file_verification.json` is not rebuilt and the comparison reports it as "not rebuilt, optional input absent"; with the file present, it must be rebuilt and match.

Each run writes `outputs/run_manifest.json` (run identifier, hashes of all code, reference and raw input files, versions) and, per stage, a record in `outputs/run_ledger.jsonl` (script and helper hashes taken before the stage runs, timing, exit status, hashes of files changed or deleted). The shipped manifest and ledger are those of the run that produced the shipped tables (Python 3.14.8, pandas 3.1.1, Linux on arm64). A second complete run under Python 3.12.15 with pandas 2.3.3 agrees with it exactly in every identifier, count, label and sign; 2,443 decimal cells differ in their last digits, all but one within 3e-12 of their value (the exception: a difference of two nearly equal numbers, 2e-11, within 2e-7 of its value). Cell-level differences: `outputs/rebuild/final_v5/`. In one environment, repeated runs reproduce every table and figure byte for byte. Both runs used one physical machine (Apple Silicon); a third run on macOS by the researcher also passed.

Stage 3 keeps two caches (the extracted scores and per-competition rows) so that an interrupted run can resume. Both are bound to a fingerprint of the stage 3 code, its helpers, its metadata and label inputs and the raw `Submissions.csv` and `Teams.csv`; if any of these changed, the run stops and asks for `CLEAN=1`.

All CSV tables are read through `scripts/csvio.py`, which converts numbers with Python's correctly rounded `float()`: the default CSV number parser of pandas 2.x and 3.0 is not correctly rounded (`scripts/diagnostics/parser_precision_check.py` measures this). It is verified for the tables this project writes, not as a general replacement for pandas.

## Status of the reports in `outputs/`

The paper states the current claims. The reports are kept as written at the time, with amendments appended where a later review changed their interpretation.

| Report | Status |
|---|---|

| `independent_reanalysis_route.md` | Stage 1 plan for proceeding without the original code. Current. |
| `stage3_report.md` | The planned results. Numbers current; its reading of drift as adaptation is superseded by the paper (drift is a description consistent with adaptation, not a measurement of it). |
| `stage4_report.md` | Exploratory follow-ups. Amended at the end: the checks rule out two specific explanations only; "selection-adjusted" means relative to an independent-resplitting reference. |
